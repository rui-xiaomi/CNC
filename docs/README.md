# docs 目录说明

本目录是 **CNC 自动化上下料客户端** 的开发文档集合。

## 文档清单与定位

| 文件 | 定位 | 权威性 |
| --- | --- | --- |
| `客户端开发文档.md` | **开发依据（权威）**。基于最新具体化要求（WPF / .NET 10 / MySQL / 仅与 PLC 通信）重写的落地开发文档，已对既有文档做缺漏审查、逻辑调整与补齐。 | 以本文为准 |
| `数据库文档.md` | **数据库设计说明**。表清单、ER 关系、字段语义、结构变化，对应 `客户端开发文档.md` §4。 | 以本文为准 |
| `sql/cnc_schema.sql` | **可执行建库脚本**。建表 + 示例初始化数据，可重复执行。 | 运行用 |
| `UI设计文档.md` | **UI 设计规范**。设计令牌、布局骨架、组件规范、各页要点、去 AI 味原则。 | 以本文为准 |
| `prototype/index.html` | **高保真原型**。浏览器打开，可点击切换 8 个页面，用真实示例数据。 | 视觉/交互验收 |
| `测试机信号表.md` | **通信契约（外部输入）**。客户端经 PLC 读写的信号定义来源，地址与数值为现场实际可用数据，开发直接据此读写。 | 实际可用 |
| `自动化标准化软件开发方案.md` | 标准化参考。早期偏服务端编排、Oracle 选型，部分内容与新约束冲突，顶部已加修订说明。 | 仅参考 |
| `CNC自动化上下料 软件开发需求方案.docx` | 原始需求方案（历史）。表结构/流程的最初来源，Oracle 选型、含直连机台逻辑。 | 历史归档，不再直接据此开发 |

## 目录约定

- 开发文档统一用 Markdown，中文正文，代码/表名/字段名用英文。
- 数据库设计、信号契约、业务流程、UI 需求集中在 `客户端开发文档.md`，不再另起平行方案文件，避免多源不一致。
- 信号地址只允许在 `测试机信号表.md` 维护一份；其他文档引用而不复制。
- 新增章节遵循"结论先行 → 约束 → 设计 → 待确认项"的写法；待确认项统一用 `> ⚠️ 待确认` 标注。
