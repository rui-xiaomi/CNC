# 智造云枢 LineOS — 演示实操手册

> 面向「第一次上手测试/调试」。全程基于**内置模拟器**（Modbus/FINS 模拟 PLC + RCS 模拟器 + 机台节拍模拟器），**无需任何真机**即可把整套流程跑通。
> 依据当前代码（Phase 1~5 + 上线缺口 + 业务流程测试 + **2026-08 P0/P1 安全门禁**）编写。命令用英文，界面按实际中文导航项描述。
>
> **本手册对应功能层级**：第一层（零件测试）+ 第二层（本机联跑，含异常注入）。第三层现场联调见 §7、`docs/现场联调配置清单.md` 与开发文档 §10。单测：`dotnet test CncLoader.sln`。

## 0. 一分钟速览（最短路径）

1. 确认已装 **MySQL 8.4** 且已建库 `cnc_auto`（见 §1.2）。
2. 确认 `src/CncLoader.App/appsettings.json` 里连接口令与本机一致（默认 `root` / `2580.wxr`），且 `UseSimulator` 都为 `true`（默认就是）。
3. 在项目根目录运行：`dotnet run --project src/CncLoader.App`
4. 窗口弹出后，标题栏应显示 **PLC 3/3**（三台模拟 PLC 在线）。
5. 按 §3 逐页点，按 §4 跑「完整上下料闭环」。

出问题先看 §6 排查。

## 1. 环境准备（只做一次）

### 1.1 运行时依赖
| 依赖 | 说明 |
|---|---|
| .NET 8 SDK | 用 `dotnet run` / `dotnet build` 需要 SDK；只跑 exe 需要 .NET 8 Desktop Runtime |
| **ASP.NET Core 8 运行时** | RCS 回调宿主 + RCS 模拟器内嵌 Kestrel，**必须装**，否则 RCS 收发回调会失败 |
| MySQL 8.x | 本机库，库名 `cnc_auto` |

检查命令：
```powershell
dotnet --info
```
`.NET runtimes installed` 里应同时能看到 `Microsoft.NETCore.App 8.x`、`Microsoft.WindowsDesktop.App 8.x`、`Microsoft.AspNetCore.App 8.x`。

### 1.2 建数据库
用本机 MySQL 客户端执行建库脚本（一次性，含 3 PLC / 3 机台 / 6→5 加工位 / 3 料架种子）：
```powershell
# 路径按本机 MySQL 安装位置调整
& "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -u root -p < docs\sql\cnc_schema.sql
```
执行后可校验：
```sql
USE cnc_auto;
SELECT COUNT(*) FROM MAS_AUTO_WORKLINE_PLC;      -- 3
SELECT COUNT(*) FROM MAS_AUTO_WORKLINE_EQUIMENT; -- 3
SELECT COUNT(*) FROM MAS_AUTO_EQUIMENT_POSITION; -- 5
SELECT COUNT(*) FROM MAS_AUTO_FRAME;            -- 3
```

### 1.3 确认 appsettings（`src/CncLoader.App/appsettings.json`）
演示态**保持默认**即可，重点几项：

```jsonc
"Database": { "User": "root", "Password": "2580.wxr", "PasswordProtected": false }, // 改成你本机口令
"Plc":  {
  "UseSimulator": true,                 // ← 模拟 PLC，必须 true 才能无真机演示
  "PollingEnabled": true                // 持续轮询信号仓；闭环节拍必须 true（false 仅供手动单步调试）
},
"Rcs":  {
  "BaseUrl": "http://127.0.0.1:8090",  // RCS 模拟器监听端口
  "CallbackPort": 9080,                 // 回调宿主监听端口
  "UseSimulator": true,                 // ← RCS 模拟器，必须 true
  "TrackerEnabled": true,               // 任务跟踪器（轮询兜底）
  "SchedulerEnabled": true,             // 上下料状态机（默认 true，可不写；置 false 关闭自动节拍）
  "ReconcileRetryIntervalMs": 5000,     // 启动对账失败后台重试间隔（必须 >0）
  "WaterMonitorEnabled": false,         // 水位自动换架，演示先关（避免误触发）
  "InventoryAutoEnabled": false,        // 定期自动盘点，演示先关（手动盘点用料架页按钮）
  "SimulatorFailureRate": 0.0,          // 想演示失败/redo 时调成 0.3~1.0
  "SimulatorCancelRate": 0.0,           // 想演示取消时调成 0.3~1.0
  "SimulatorNgRate": 0.3                // ← 机台出 NG 的概率（0=全 OK，0.3=三成 NG 走 NG 分流）
}
```
> - 口令改动后：`PasswordProtected` 保持 `false` 即用明文（仅本机开发，别提交进 git）。
> - **⚠ 模拟器四项（`SimulatorFailureRate`/`SimulatorCancelRate`/`SimulatorNgRate`/延时）在启动时读取、不热加载**：改完必须**重启 App** 才生效。启动日志会打印「失败率 N% 取消率 N%」，以日志为准。
> - `SimulatorNgRate` 当前默认 `0.3`：跑闭环会有约三成的件走 NG 分流。想只看全 OK 流程，先设 `0.0` 再重启。

### 1.4 Windows「智能应用控制」（历史坑）
若双击 exe 报 `FileLoadException 0x800711C7 应用程序控制策略已终止此文件`：到 **Windows 安全中心 → 应用和浏览器控制 → 智能应用控制** 关掉。当前本机已关闭，`dotnet run` 一般不受影响。

## 2. 启动与「启动后应该看到什么」

### 2.1 启动方式（二选一）
```powershell
# 方式 A：开发调试（推荐，能看控制台/热重编译）
dotnet run --project src/CncLoader.App

# 方式 B：先构建再跑 exe
dotnet build
.\src\CncLoader.App\bin\Debug\net8.0-windows\CncLoader.App.exe
```
> **切记只开一个实例**。开第二个会抢模拟器端口（15001-15003 / 8090 / 9080），导致连接混乱。

### 2.2 启动自检（后台自动执行，看日志确认）
窗口会**先弹出**，随后后台跑自检。日志文件：`src/CncLoader.App/bin/Debug/net8.0-windows/logs/cncloader-*.log`。正常应看到：
- `数据库连通 ✓ 线体=1 PLC=3 机台=3 加工位=5 点位=… 料架=3`
- `轮询一轮完成，读到 N 个点位。`
- `端到端验证 ✓ PLC#? 读 D1006 = ?`

### 2.3 主窗口标志
- 左侧 8+2 项导航（运行/配置/设备/物流分组）。
- 顶部标题栏：**PLC 3/3**（三台逻辑 PLC 全在线）、协议 `PLC FINS`（种子默认；也可 ModbusTCP）、时钟、心跳、告警角标。
- 默认停在「监控看板」。

模拟 PLC 端口对应关系（排查用）：Modbus=15000+PLC_ID（PLC1→`15001`…），FINS=16000+PLC_ID（PLC1→`16001`…）。**起哪种模拟器取决于库里每台 PLC 的 `PLC_READ_WAY`**（ModbusTCP / FINS）；标题栏协议区会显示实际协议（多协议用 `/` 连接）。现场共物理 PLC 时，三行配置可填相同 IP（如 `192.168.250.1`），逻辑上仍是一机一 `PLC_ID`。

## 3. 逐页演示清单

> 每页操作后，成功会有右上角 Growl 气泡提示；失败也会提示并写日志。

### 3.1 监控看板（`dash`）
- 4 个统计卡：在线机台 / 当班 OK / 当班 NG / 未处理告警。
- 加工位卡片列表：状态徽标 + 中文态（等待上料/上料中/运送中/加工中/…）。
- 最近加工记录表。
- **静态时**加工位多为「等待上料/离线」；跑 §4 闭环后卡片会随节拍变化。

### 3.2 线体 / 工序 / 机台 管理（`line` / `craft` / `eq`）
配置类 CRUD，验证读写库：
1. **线体管理**：左列表选「线体1」，右表单改名称→「保存」→ Growl 成功。
2. **工序管理**：按线体过滤，选工序编辑保存。
3. **机台管理**：列表按工序过滤；
   - 「新增」→ 模态框填编号/名称/工序/关联 PLC（含「无」）→ 保存，自动建 2 个加工位。
   - 「编辑」→ 编号只读，可改名称/编码/类型/工序/PLC。
   - 「删除」→ 有引用（点位/绑定）会 Growl 提示引用数拒删；无引用二次确认后软删。
- 删除校验可直接用种子验证：删「线体1」会被工序引用而拒删；删「机台1(内长宽)」会被点位引用而拒删。

### 3.3 PLC 管理（`plc`）
一页多 tab，核心设备调试页：
1. **PLC 列表**：3 台（一机一逻辑 PLC），状态灯。逐台/全部「连接/断开」。
2. **读面板**：选机台 → 「单次读」或「周期轮询」→ 看原始值 + 语义值（ON 绿 / OFF 灰）。
3. **写面板**：选「POS_TEST_START」类写点 → 填值 → **二次确认** → 先落 `MAS_AUTO_DEVICE_LOG` 流水 → 下发 → 回读校验。
4. **点位映射**：列表展示；可编辑信号 KEY/ON/OFF/长度（即时提交）；「保存全部」批量写；「信号表导入」批量；软删。
5. **告警 / 通信流水**：实时展示；通信失败会写 `MAS_AUTO_ALARM_EVENT`。
6. **PLC 配置 CRUD**：新增（建议 PlcId + 唯一校验）/ 编辑（PlcId 只读，在线则先断开）/ 删除（引用校验+软删）。编辑对话框「对应机台」是下拉，可反向绑定。

### 3.4 RCS 任务（`rcs`）★ 重点
四块（连接&下发 / 任务列表 / 报文流水 / 位置映射）。**RCS 模拟器已内置**，下发后秒级自动回推状态。

**手动下发测试（连接&下发 tab）：**
1. 选类型「搬运 transit」，From/To 用默认 `101101 → 201101`，优先级 5 → 「下发」。
2. 终端出现 `> transitTask …` `< OK …ms`；任务列表新增一条 `CREATED/DISPATCHED`。
3. 约 1.5~4 秒后：终端出现 `↩ … → COMPLETED`，任务列表该行翻 `COMPLETED`（模拟器回推 + 跟踪器兜底双通道）。
4. 「抓取 grab」：填源/目标孔位（默认 101/101→201/101）→ 下发，同样回推完成。
5. 「识别 identifyQR」：填起始孔位 101 / 数量 3 → 下发，回推 `scanTaskStatus`，终端显示「扫得 3 码」。

**取消 / 重试：**
- 下发后 taskId 会自动回填到「操作 taskId」框。
- 「取消」→ 发 cancelTask；想稳定复现取消，把 `SimulatorCancelRate` 设 1.0 重启再下发，任务会 `CANCELED` 并产 `RCS_CANCELED` 告警，随后可点「确认取消已处理」。
- 「redo」→ 同 taskId 重发。料架路径若预记已回滚，会先再预记再下发；预记失败则拒发。想看**自动 redo**：把 `SimulatorFailureRate` 设 1.0 重启，下发后失败会自动 redo ≤3 次，超限产 `RCS_REDO_LIMIT` 告警。

**报文流水 tab：** 按 方向/接口/taskId/条数 筛选；排查时可关「自动刷新」避免被回调刷走。

**换架 / 空托盘回收（连接&下发 tab 下部）：** 需先在位置映射录入缓存区/回收区（见 §4.1、§5）。填机台 ID + 角色「换架」→ 终端出 `↻ 换架 …` 两发进度。

**位置映射 tab：** 就是 §4.1 要录的 `LOCATION_MAP`，也可在此页「新增/保存/删除」。

### 3.5 料架管理（`frame`）
- 料架列表 + 绑定关系（演示「一架两用」：中转架既是内长宽下料架又是 A 基准上料架）。
- 分层槽位卡片：按状态着色（占用蓝 / 预记橙 / 锁定）。
- **人工校正**：点某槽位 → 改物料码 + 状态下拉（仅空/占用/锁定，**不含预记**）→ 「校正保存」。预记槽会 Warning「已被任务预记，不能人工校正」，不得 Success。NG 闭环可勾「仅 NG 架」→ 点占用槽 → 「置空释放」（预记槽同样拒清）。
- **发起盘点**：选料架 → 填起始孔位（三位数、百位=层，如 101）+ 数量 → 「发起盘点」→ 下发 identifyQR → 回推后按层/层内位顺序校正；遇预记槽跳过并汇总 Warning。
- 物料反查：输入物料码高亮所在槽位。

### 3.6 AGV / 扫码枪（`agv` / `scan`）— 仅连通性测试
- **AGV**：填名称/通信方式(HTTP REST·Socket)/地址 → 「测试连接」→ 终端出 `> GET …` `< 200 OK Nms` 或 `< ERROR …`，状态徽标「连通 Nms / 不通」。（没有真 AGV 时填个不通地址看红灯即可。）
- **扫码枪**：选模式(TCP 服务端/客户端)+端口 → 「开始监听」→ 徽标「已连接 N」。可用工具往该端口发一行文本（CR/LF 结尾）验证「最近扫码」表刷新。
  - 快速造数据：`Test-NetConnection` 不够，可用 `ncat`/`telnet` 或简单 PowerShell TcpClient 发送字符串。

### 3.7 日志 / 告警（`log`）
- **告警明细** tab：时间/级别/类型/消息/状态；「只看未处理」筛选、「标记已处理」、「全部删除」(物理硬删，二次确认)。§3.4 造的 RCS 告警会在这里。
- **应用日志** tab：读最新 `logs/*.log` 尾部，按级别筛选。排查首选。

## 4. 完整上下料闭环演示（核心，★★）

这是把「PLC 信号 → 调度器状态机 → RCS 下发/回调/跟踪 → PLC 复核 → 写启动 → 加工记录 → 看板」串起来的自动节拍。调度器默认开启（`SchedulerEnabled=true`），但**需要先录入位置映射**，否则找不到路由会告警停下。

### 4.1 前置：建库即就绪（LOCATION_MAP + 三道串行已并入 cnc_schema.sql）
**`docs/sql/cnc_schema.sql` 已是单一权威建库脚本**，一次执行即建出**完整三道串行演示库**——含：
- 三道工序 node1/2/3（内长宽→A基准→平面度）+ 机台挂序；
- 5 个料架 + 绑定（上料 frame1 / EQ2中转 frame2 / EQ3中转 frame92 / 下料 frame3 / NG 共用 frame91，均为 10 层×2=20 槽）；
- 全套 `LOCATION_MAP`（现场搬运：上料 101 / 下料 303 / 中转 301·302 / NG 401 均为 10×2 cell；内长宽 201101·201102；缓存/回收区仍为演示码）；
- 上料架101 补满 20 物料（`101101/101102`…`101191/101192`，与槽位 cell 相同）。

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -u root -p < docs\sql\cnc_schema.sql
```
> 建库/重置一步到位。**再无需任何额外种子脚本**（原 demo_seed / test_routing / three_stage / migration_* 已全部并入本脚本并删除）。
> 料架跑到见底（上料架空）后，**重跑一次 `cnc_schema.sql` 即重置补满**。

也可在「RCS 任务 → 位置映射」页手动「新增」。匹配规则（来自代码）：
- 加工位 cell：`RCS_TYPE='cell' AND EQUIMENT_ID AND POSITION_ID`（内长宽 201101/201102）
- 料架站点：`RCS_TYPE='shelf' AND FRAME_ID`（101/301/302/401）；料架槽 cell：`RCS_TYPE='cell' AND FRAME_ID`（101101…）；换架/回收区：`LOC_TYPE='AREA' AND LOC_NAME='FULL_BUFFER'/'EMPTY_BUFFER'/'PALLET_RETURN'`
- 现场搬运不走 `LOAD_AREA`/`UNLOAD_AREA`（与 101/301 shelf 同码会歧义拒发）

> 建库种子已按现场搬运规则写入（101/201/301/302/401）。编码或绑定不对就重跑 `cnc_schema.sql`。**缺 LOCATION_MAP 时换架/盘点/料架路由会拒发并告警，不再使用 `FRAME-{id}` 假码。**

建库后**重启 App**（调度器在启动时装载路由/绑定缓存）即可跑闭环。

### 4.2 观察节拍
打开「监控看板」，EQ01-工位1 卡片应自动循环：
```
等待上料 → 上料派发中 → 运送中 →（PLC 复核有料）→ 已上料
      → 写 POS_TEST_START=1 → 加工中 →（约2s）→ 加工完成OK
      → 下料派发中 → 运送中 →（PLC 复核无料）→ 已下料
      → 写 POS_TEST_START=2 → 回到 等待上料
```
同时：
- 「RCS 任务」页任务列表会不断出现搬运任务并翻 COMPLETED。
- 「当班 OK」/「当班 NG」计数递增；「最近加工记录」表新增行（机台/工位/物料/结果/耗时）。
- 双加工位机台会**并行**跑（各自独立状态机）。

**下料终点由路由决策（「上线缺口 Step4」完整分流，不再是简单单工位回收）：**
| 情形 | 去向 |
|---|---|
| 检测 NG | NG 架(role3)；未绑 NG 架 → 回退下料架/下料区（仅 warning） |
| OK 且有下一工序 | 本机下料架（同时是下游上料架）。**无工位直送** |
| OK 且是末道工序 | 下料架303；无 shelf/cell 则拒发（勿回退 UNLOAD_AREA=301） |

> 一架两用：EQ01 内长宽从 101 取，OK→301；EQ02 A基准从 301 取，OK→302；EQ03 平面度从 302 取，OK→303；任一道 NG→401。绑定以 `cnc_schema.sql` 种子或界面配置为准。想看更多 NG 分流把 `SimulatorNgRate` 调大重启。

### 4.3 演示异常与安全底线（对应第二层「关键异常注入」清单）

| 异常 | 怎么复现 | 期望结果（验收点） |
|---|---|---|
| **① 复核不过：RCS 报完成但 PLC 没置「有料」信号** | `SimulatorSkipMaterialArrival=true` 重启后跑节拍（或代码注入 `CncMachineSimulator.SkipMaterialArrival`） | 该加工位进 **Alarm 粘滞**，**绝不写 POS_TEST_START 启动信号**；看板告警卡点「恢复」→ 回 WaitLoad。测完务必改回 `false` 并重启 |
| **② 任务失败 → 自动 redo** | `SimulatorFailureRate=1.0` 重启后下发/跑节拍 | 失败自动 redo ≤ `MaxAutoRedo`(3) 次，**用的是同一个 taskId**，`REDO_COUNT` 递增；料架路径先补预记再 Claim/下发，预记失败不耗次数；超限产 `RCS_REDO_LIMIT` 告警 |
| **③ 任务取消 → 人工工单 + 锁点位 + 确认解锁** | `SimulatorCancelRate=1.0` 重启后下发；或 RCS 页手动「取消」 | 任务翻 `CANCELED` + 产 `RCS_CANCELED` 告警（人工工单）；点「确认取消已处理」后 `CANCEL_MANUAL_FLAG=1` 解锁 |
| **④ 跑到一半强杀程序重启 → 对账恢复** | 节拍跑起来后直接关掉 App 进程，再 `dotnet run` 重启 | 启动做**三方对账**（①未完结任务绑回 → ①b query 终态按 `SlotSettlement` 收口 → ②陈旧预记回滚 → ③PLC 有料无任务→ALARM），**全部成功才开闸**；失败则看板显示对账未完成并按 `ReconcileRetryIntervalMs` 重试，不开自动派工。①b：HasMat 符合才 Confirm；明确不符 Rollback+Alarm；**未知保持预记与工位绑定，不回 WaitLoad、不 latch Alarm**。失败/取消/非 COMPLETED 陈旧预记须回滚，不得残留 `SLOT_STATE=3` |
| **⑤ 软删配置后新派工** | 配置页软删某机台/工序/位置映射后观察自动派工或手动下发 | 新外部执行拒发（fail-closed）；历史任务 Confirm/Rollback/Query 仍可收口 |

- **派工失败（路由缺失/下发失败）**：该位进 Alarm 粘滞，不会 500ms 疯狂重试（Session 30 修复）。
- **HasMat 未知**：读失败不得当无料；连续未知达阈 → Alarm，不写 `POS_TEST_START`；COMPLETED 预记未知时不落账也不回滚。
- 告警统一进「日志/告警」页（§3.7），可「标记已处理」。

### 4.4 关掉闭环
想只演示单页、不让节拍一直跑：把 `Rcs.SchedulerEnabled` 设 `false` 重启即可（当前 appsettings 未显式列出该项，默认 true；可手动加 `"SchedulerEnabled": false`）。

## 5. 换架 / 水位 / 盘点 进阶演示（可选）
缓存区/回收区/料架站点映射 §4.1 的种子脚本已包含（`FULL_BUFFER`/`EMPTY_BUFFER`/`PALLET_RETURN` + 3 个料架 shelf 行），跑过脚本即可直接演示。
- **手动换架**：RCS 页填机台 ID + 角色「换架」→ 看两发（先拉旧架 priority=9 → 后送新架）+ 终端进度 + 换架事务 DataGrid。
- **空托盘回收**：填回收点位 → 「回收」。
- **手动盘点**：料架页选料架 → 填起始孔位 + 数量 → 「发起盘点」→ 下发 identifyQR → 模拟器回推后槽位按扫描结果全量校正 + Growl（见 §3.5）。这是演示盘点的推荐方式。
- **水位自动换架**：`WaterMonitorEnabled=true` 才生效。料架→机台绑定反查已实装（「上线缺口 Step1」：空架偏上料角色、满架偏非上料角色；拿不到真实绑定才跳过）。**但演示态仍建议保持关闭**——种子料架启动即可能触发换架（上料架空 / 下料架接近满 / 中转架空都会触发），接真机会真指挥 AGV；要演示先确认 `FRAME_BIND` 绑定齐全再开，测完改回 `false` 重启。
- **定期自动盘点**：`InventoryAutoEnabled=true` + `InventoryIntervalMinutes` 生效。触发：后台每 30s 检查，距上次 ≥ 间隔且 RCS 空闲（无派工/盘点/换架）时逐架 identifyQR（串行）；**启动后首检立刻到期**（不必真等满间隔）。演示态默认关，手动盘点即可。测完改回 `false` 重启。

## 6. 常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 标题栏 `PLC --/--` 或 `0/3` | 模拟器没起（`Plc.UseSimulator` 非 true）/ 端口被占（开了多个实例）。看日志 `PLC 运行时装配`。 |
| 对账 OneB / queryTask 打到现场 IP 或查无任务 | 库表 `MAS_AUTO_WORKLINE_AGV` 仍是现场地址。确认 `Rcs.UseSimulator=true` 后重启；日志应有「出站改写为本机」。同时只留一个 App 实例。现场查询字段是 `Id`（本地 taskId），不是回包号。 |
| 启动日志「数据库未连通」 | 口令/库名错，或没执行 `cnc_schema.sql`。用 `mysql.exe` 手动连一次验证。 |
| RCS 下发 `< OK` 但任务不翻 COMPLETED | ASP.NET Core 8 运行时没装（回调宿主/模拟器起不来）；或 `Rcs.UseSimulator=false`。看日志有无 Kestrel 监听/端口占用错误。 |
| 回调到了但页面不刷新 | 已修（Session 23 跨线程 marshal）。若仍不刷，确认「自动刷新」勾选、看终端是否有 `↩`。 |
| 监控看板加工位一直「等待上料」不动 | LOCATION_MAP 没录（§4.1）或 `SchedulerEnabled=false`；录完要**重启**。 |
| 某加工位卡在「告警」 | 复核不过/路由缺失/下发失败。查日志定位；恢复需 `ResetAlarm`（调度器接口，UI 触发点见告警处理）。 |
| 双击 exe 秒退/报应用控制策略 | 关智能应用控制（§1.4），或用 `dotnet run`。 |
| 端口冲突（15001/8090/9080） | 关掉多余实例；或改 appsettings 端口。 |

**调试三板斧：**
1. 先看 `logs/cncloader-*.log`（或「日志/告警」页应用日志 tab）。
2. RCS 相关看「报文流水」tab（OUT 是我方发、IN 是回调收）+ `MAS_AUTO_RCS_MSG_LOG` 表。
3. PLC 相关用「PLC 管理→读面板」单次读确认链路，写操作看 `MAS_AUTO_DEVICE_LOG`。

## 7. 接真机时要改什么（现场，非演示）

**完整勾选清单（推荐主入口）**：[`现场联调配置清单.md`](现场联调配置清单.md)  
**示例配置（复制改名，勿提交真实口令）**：`src/CncLoader.App/appsettings.Field.example.json`

摘要：
- `Plc.UseSimulator=false` + 真实 PLC IP/端口；FINS 机台确认**节点号**（当前默认取 IP 末段，不符要改配置或换协议）。
- `Rcs.UseSimulator=false` + 真实 `BaseUrl`；回调 `CallbackHost/CallbackPort` 报备 RCS 并开防火墙（改端口须重启）。
- 首轮关闭 `WaterMonitorEnabled` / `InventoryAutoEnabled`；自动派工可用 `SchedulerEnabled=false` 先验通再开。
- LOCATION_MAP 录**真实**点位编码（上料区/下料区/各加工位 cell/缓存区/回收区/料架站点）；FRAME_BIND 含中转/NG。
- 缺 LOCATION_MAP 时换架/盘点/料架路由会拒发并告警，不再使用 `FRAME-{id}` 假码。
- 料架绑定、点位地址、FINS 节点等须 **待真机验证** 后再勾完成。
