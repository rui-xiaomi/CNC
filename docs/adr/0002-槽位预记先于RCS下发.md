# ADR-0002：自动派工先槽位预记，后 RCS 下发

- 状态：Accepted
- 日期：2026-08-04

## 背景

自动上下料当前先向 RCS 下发任务，再执行槽位预记。外部写入者在该窗口抢占槽位时，
实物任务可能已执行而本地账未锁定。事后取消不能消除 RCS 已接单或已启动的风险。

## 决策

自动派工由调度器预生成 taskId，并按以下顺序执行：

1. 使用 taskId 对源槽或目标槽做条件原子预记；
2. 仅预记成功后，使用同一 taskId 调用 RCS；
3. 下发失败或异常时补偿回滚预记；
4. 下发成功后保留预记，沿用现有完成落账、失败/取消回滚流程。

直接交接使用 `_expectedInbound` 作为进程内预登记，遵守相同先登记后下发顺序；
预登记先为 Pending，RCS 下发成功后才转为 Dispatched，目标工位不得提前消费 Pending 登记。
没有料架账的命名区搬运不创建虚假槽位记录。

## 结果

- 预记失败不再产生可执行 RCS 任务。
- 数据库条件更新继续承担并发仲裁，只有预记成功者可以下发。
- 数据库与 RCS 之间仍是补偿式事务，不宣称具备原子分布式提交能力。
- 手工 RCS 调用不传 taskId 时保持由服务生成，兼容现有入口。
