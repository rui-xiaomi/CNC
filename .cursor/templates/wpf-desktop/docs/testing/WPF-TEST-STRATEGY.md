# WPF 测试策略

> 按项目真实测试框架和命令补全。未执行的层级必须报告为“未验证”。

## 测试矩阵

| 层级 | 覆盖内容 | 项目/框架 | 命令 | CI 环境 |
|---|---|---|---|---|
| 领域/ViewModel | 状态转换、命令、校验、错误恢复 | 待确认 | 待确认 | 普通 Windows runner |
| STA WPF 集成 | XAML、Binding、资源、Dispatcher、控件属性 | 待确认 | 待确认 | Windows + STA |
| UI Automation | 启动、导航、编辑、保存、错误恢复 | FlaUI/WinAppDriver/既有框架 | 待确认 | 交互式 Windows Session |
| 人工 QA | DPI、主题、多显示器、输入法、视觉、安装升级 | 检查清单 | 人工 | 目标 Windows 环境 |

## 硬规则

- STA 测试显式声明 STA，不依赖测试运行器默认线程模型。
- UI Automation 使用条件等待，不用固定 `Sleep` 代替状态同步。
- 每个交互元素提供稳定的 `AutomationProperties.Name` 或项目统一 AutomationId。
- 测试失败保存日志、截图和自动化树；不得吞异常、降断言或硬编码期望值。
- 无交互式 Windows Session 时，UI Automation 必须显示为 skipped/未运行，不得当作通过。
